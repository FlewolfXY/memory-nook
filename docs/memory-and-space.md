# 长短记忆、纪念物与空间

2026-09-08 · 产品约定与实现设计。产品方向依据用户本轮补充；下述 v2 数据结构为待实施设计，当前应用仍使用 v1。

## 1. 用户在保存什么

输入长度不决定记忆的重要性，也不决定它必须长成什么。照片、一句话、一篇长文都从同一个记录入口进入；不先问用户“这是瞬间还是日记”。允许只有文字、只有照片、图文混合。多段文字、多张照片是数据结构应支持的能力，界面可逐步提供。

短内容：地铁车窗、昏黄灯光、橙绿座位，加一句“刚才有种奇异的感觉”。可以立即收好，晚些时候再整理。

长内容：一篇关于搬家、毕业或漫长求职期的记录。全文应能阅读、编辑、导出；生成纪念物时可以表达整篇的一个主题，也可以由用户圈定其中一段。不要求把所有细节压进一个模型。

长期体验：记忆匣保存完整生活材料，小屋和院子陈列用户选择的表达。数量增长优先通过收纳、搜索和用户选择展示来处理。

## 2. 五个概念，各自保持稳定

| 概念 | 负责什么 | 示例 | 不承担什么 |
|---|---|---|---|
| Memory | 原始生活记录与版本 | 一篇长文、三张照片、发生日期 | 不保存鱼每一帧的位置 |
| Feature | 有出处的候选表达细节 | 原文里的“橙绿色”、照片采到的颜色 | 不替代原文，不充当人格诊断 |
| Souvenir | 用户留下的表达形态 | 相框、小册子、玻璃灯、一条鱼 | 不等于必须新建一条生活记录 |
| Placement | 这件物品安放在哪、怎样安放 | 书架局部坐标、院子池塘栖息区域 | 不决定原记忆属于哪类心情 |
| Space | 可逛、可停留、可布置的环境 | 客厅、院子；院子中的池塘是一个区域 | 不成为强制分类目录 |

2026-09-09 用户纠正后的默认约定：一个 Memory 可以暂时没有 Souvenir；一张照片默认只对应一个物件。换空间或表达形态是移动、重塑，不自动复制。当前实现将家具关联与独立摆件安放互斥，并合并相同图片字符串的展示关联；不声称能识别裁剪、压缩等视觉近似照片。

一件 Souvenir 可在用户主动 Cross 时引用多段 Memory，保留来源谱系。数据层可扩展多来源，不代表产品默认把同一张照片重复挂满房间。未来若允许主动再做一件，必须另作明确设计，本轮没有该入口。

摆件收回匣子，只移除 Placement；原记录与纪念物仍在。原文更新不会在用户不知情时重塑已经熟悉的物件。生成物记录其使用的原文版本，用户可主动重做。

## 3. 长文如何产生值得留下的东西

完整保存 → 选择表达片段（默认可为全文）→ 提出少量有出处的细节 → 用户认领或修改 → 选择形态 → 安放。

保存成功独立于后续提取、生成和三维加载。可以只写完就走。生成失败、超时或不喜欢结果，都不能让原记录丢失。

### 可以提取的内容

- 具体物件与场景：橙绿座椅、贴满胶带的纸箱、窗边的一盏灯。
- 光、颜色、材质与声音：反光、昏黄、玻璃感、断续的雨声。
- 动作、关系或变化：从一个地方搬到另一个地方；终于把某件东西摆好。
- 用户明确写出的感觉与重要句子。推测出的主题必须作为可改的建议。

不能把长文先压成一句摘要，再仅凭摘要塑形。候选细节要指回原始段落；摘要只能辅助浏览。长文超过模型单次处理能力时，按段落保留顺序处理，再合并有出处的候选。尚未处理的范围和失败状态不能伪装成完整分析。

初期建议最多展示 2–3 个候选，避免让保存变成一场标注工作。用户也可以直接输入“我只想留下那个绿色的窗台”，或跳过提取选原照片。

**虚构的设计例子，非用户真实记录：**一篇搬家长文中有“纸箱还没拆，我先把旧台灯放到了窗边”。可提议一个带纸箱纹理的小灯座，保留“先安放台灯”这个动作；若另有关于夜雨的段落，也可以单独成为一条尾鳍带雨纹的鱼。两个表达都指回同一篇全文与各自取材段落。

物件不能只因“都是绿色”就宣称理解了这篇长文。最低验收是：主人看过后能说出它保留了哪一处细节，并愿意留下；不要求旁人猜出私人故事。

### 事实、提议与艺术处理

内部保留三类来源：用户选择 / 从图片等材料测得 / 模型推测。原照片的采色与艺术化后的流彩色分开记录。外观加强饱和度属于塑形选择，不能改写采色事实。

用户界面只需在合适时说清“取自这一句”“取自照片颜色”“试着做成这样”；无需展示置信度仪表盘。现有程序仅有采色、几何模板与颜色组合，语义提取和生成模型尚未接入。

## 4. v2 数据约定（待实现）

下表描述逻辑结构，不强制换数据库或技术栈。初期仍可用当前 IndexedDB；表示、渲染和原文读写应经由独立的数据接口连接。

| 对象 | 关键字段 | 约束 |
|---|---|---|
| Memory | id, title?, createdAt, updatedAt, happenedAt?, currentRevisionId | 记录时间与事情发生时间分开；不知道日期时允许空值，时间范围也应有表达 |
| MemoryRevision | id, memoryId, blocks[], createdAt | 版本中的原文字节与段落顺序保持；blocks 可为 text 或 image，未来再加入音频 |
| Asset | id, mimeType, byteLength, checksum, blobRef | 原附件独立保存；缩略图另存，不以缩略图替换原图 |
| Feature | id, memoryRevisionId, kind, value, evidence[], method | method 为 user / sampled / inferred；推测不能写成用户原话 |
| Souvenir | id, title?, sourceRefs[], representation, parentSouvenirIds[], createdAt | 来源不依赖当前所在空间；重新生成前一版本可追溯 |
| Representation | family, templateId, templateVersion, seed, params, featureIds[], method | family 可为 literal / object / living；参数由对应模板校验 |
| Placement | id, souvenirId, spaceId, mode, anchorId?, transform?, habitat? | mode 为 surface / wall / swim / rooted；变换字段随 mode 使用，避免万能坐标袋 |
| Space | id, kind, layoutVersion, anchors[], regions[] | 使用稳定语义 ID；区域声明可以承载哪些摆放方式 |

引用片段时保存 revisionId、blockId、start/end 与 quote。文本偏移采用前端一致的 UTF-16 code unit、左闭右开区间；校验 quote 与切片相符。版本是引用依据；用户编辑后，新候选引用新版本，不把旧偏移直接套到新文字上。图片来源可以引用 assetId 及可选的规范化裁剪区域。

Souvenir 的来源引用可以多对多，来源谱系必须可遍历；由两件旧纪念物形成的新物件保留 parentSouvenirIds，并解析到实际原记录。导入时检查不存在自指、循环或悬空引用。

删除区分“从空间收起”“删除纪念物”“删除原记录”。删除原记录前列明受影响的物件及引用的原文版本；若用户确认彻底删除，旧版本和媒体也必须纳入清理，不以版本历史暗中保留。共享附件仅在没有其他有效引用时清理。导出须包含可恢复所需的来源、相关版本、附件、物件和布局。

### 灵活的边界

输入结构可扩展，已支持字段仍要有明确类型、版本和校验。不可使用任意 JSON 直接驱动材质、执行脚本或构造 HTML。

不把 1,000 字作为产品设定。实现仍需要公开、可解释的文件和存储上限：在写入前提示，允许分篇或稍后继续，不静默截断。首版长文以 10,000 字完整保存和恢复作为验收样本；这不是宣称无限容量，也不是最终长度上限。

长文编辑应支持可恢复草稿，关闭与切换空间前处理尚未保存的变化。阶段验收检查换行、中文、emoji 与引号，不能只检查字数。

## 5. 空间怎样帮助表达

| 空间或区域 | 擅长的观看、安放方式 | 例子 |
|---|---|---|
| 客厅的桌面、书架、墙面 | 拿起、翻阅、精心陈列 | 照片、信、小册子、玻璃灯 |
| 院子的石台、长凳、花盆边 | 在户外停留，摆放小物 | 同一盏灯、一块旅行石、一封信 |
| 院子的池塘 | 看游动、触水回应、重新遇见 | 承载记忆的流彩鱼，后续可有水母或其他生命 |
| 匣子与回顾索引 | 找完整原文，按时间或文字检索 | 包括没有生成物、没有陈列的记录 |

空间可以建议合适表达，但不规定“开心在客厅、难过在池塘”或“长文必须变成书”。物理承载方式有边界：鱼住在水域，纸卡放在能承载的表面；来源内容不受这类限制。

未来把水生表示带回室内时，可以移动到兼容水域；如果改成桌上雕塑，是一次用户选择的重新塑形，不是暗中变换。当前院子只设计一个池塘，不因此同时建设多个水族馆。

## 6. 时间与关联

家与院子展现现在。物件详情提供生活发生时间、原文版本与来源；纪念物的生成时间另列，不把今天生成的鱼冒充今天发生的记忆。

原文、物件与摆放的关系本身就能连接过去和现在。同一条旧记忆可以今天重新表达；两段不同时期的记录可以共同塑造新物件。自动发现候选联系以后再做，不要求先拥有聚类引擎才能实现主动组合。

游动路线、转向与涟漪是场景行为，不自动解释成人生寓意。只有真实发生且值得留下的动作，如用户认领了新物件或将它搬到窗边，才可能形成轻量历史记录；不逐帧写数据库。

## 7. 从当前实现走过去

现状核对：dist/app.mjs 的创建、编辑与备份校验均限制 note 为 1,000 字。一个 record 同时含 note/image、form/palette 与 spot/position/parentId，当前是一条记录一个物件。只删除 maxlength 不足以完成长文支持，导入校验和展示也必须一起改。

迁移要求：先读取旧备份到隔离的 v2 候选状态，检查数量、全文、图片、来源关系与变换；通过后把内容、附件与布局作为一致快照写入。失败保持 v1 不变，避免记忆成功但布局失败。原备份保留，重复迁移不产生重复物件。

旧组合灯的 note 是程序合成说明，不是用户新写的生活记录。迁移时应作为纪念物说明保留，parents 映射为来源谱系，不能造出一篇伪原文。

旧家具使用 item-N 遍历序号。后续客厅故事版本已经固定全部 48 个旧身份，迁移为 living-room/ 下的语义 ID；furnishing-data.mjs 保存对应关系。新增院子用独立命名空间，不因插入新网格改变旧家具身份。

本文件描述的完整原记录/表示/摆放模型尚未实施。后续客厅故事版本仅新增独立的家具来源关联、布局身份迁移与备份格式 2；不等于完成本文件的 MemoryRevision 等结构。应用输入仍限 1,000 字。实现顺序和验收见 CURRENT_SLICE.md。
