# Memory Nook · 当前实现审计

审计日期：2026-09-09 UTC。编号：AUD-001。应用基准：受管源码 `8e42b5d50186dd21806c335882b2973a33eafe3e` / Sites 版本 10；公开源码 [9dfe407](https://github.com/FlewolfXY/memory-nook/commit/9dfe4070c133035a6981397dcfd5130460f20de7)。本轮是审计与项目记录更新，未改应用画面、记忆示例或浏览器数据。

## 1. 结论与下一步判断

目前最有价值的成果，是一处已有审美基准、可以亲手布置、能通向原始图文的三维空间。它具备记忆产品的基础路径；“这件东西让我重新想起自己的那个片刻”仍缺少足够有力的体验证据。

继续增加家具和房间，暂时不会解决最核心的问题。当前应投入三件事：让内容可靠地留下；让少量纪念物能被主人认出来；让第二次回来时有一个与自己有关、可以忽略的邀请。现有小屋和院子足够承载这一轮验证。

项目目标仍是自用满意和作品集出彩。现有用户反馈支持保留小屋比例、童话风和空间操作；没有证据支持“已验证长期留存”或“已发现规模化数字家需求”。功能、审美和自用价值分开记录，避免用一个完成百分比混过去。

## 2. 产品基准

现实中的人经历一个瞬间，那个瞬间在这里获得一种可安放、可重访的形态。照片、简短笔记和未来的长文是来源，虚拟物件是表达，位置由用户决定。

用户明确举过：放学后的晚霞、下课时雨天的窗子。抱枕可以承载晚霞的颜色和纹理；不能据此替用户编出“亲手缝了这只抱枕”。真实感来自视角、时间、一个具体细节，以及这个人为何想留下它。无须虚构一位住户或完整人生。

默认一张照片只展示为一个物件。原始记录不因换形态、换位置而消失。Cross 是主动形成的多来源作品，不能冒充新发生的生活事件。池塘允许另一种观看与回应，也应始终能回到来源。

## 4. 当前到底实现了什么

| 用户路径 | 当前事实 | 与目标的差距 |
|---|---|---|
| 进入与停留 | 等距小屋、木材与柔和软装、昼夜按钮、可关闭的合成旋律 | 有被接受的视觉方向；环境偏好不跨刷新保存，音乐仍是循环短旋律 |
| 留下片刻 | 照片或文字均可；“先收好”先写入，再可选塑形 | 一张图、1000 字；没有自动草稿，日期必填；不支持长文、录音或多图 |
| 塑形 | 卡片、相框、叠色灯、黏土风景、流彩鱼；书/抱枕等也可直接绑定来源 | 固定模板加采色；文字内容未参与模型细节；没有在线 AI |
| 安放 | 桌面等 8 个命名落点（客厅 6、院子 2），每点最多 3 件；布置模式可继续拖动和调高度 | 第一次放置依赖光圈，精细自由摆放另进布置模式；暂无单击拿起再单击放下 |
| 布置家具 | 56 个稳定家具身份，其中 48 个兼容旧室内布局；默认可见 40 件家具 | 建筑、路径和固定绿化不进库存；没有通用碰撞/吸附保障，触屏效果待验 |
| 读来源 | 点物件/鱼看照片、日期、笔记；编辑、收起、删除；部分物件可展开原始采色与协调色 | 除配色外，“为什么这个片刻长成这样”表达薄弱；来源和表现未分版本 |
| 找回 | 记忆匣按日期排序，按标题/笔记文本搜索 | 搜索在 change 时执行；没有时间范围、内容来源类型或只看自己的筛选 |
| 到院子 | 边中点伸出的三维箭头小径；院子悬停门半开，点击回室内；键盘有等价入口 | 白色踏石仍在；切换直接换场景，没有过渡或位置连续性设计 |
| 池塘回应 | 大池塘、两条默认鱼、涟漪；点水吸引已有鱼，点鱼读来源 | 仅鱼；没有水母、珊瑚、聚群、持久生长；水面为视觉着色器 |
| 两个时间相遇 | 手选两条记录，拼取三色形成灯，parents 可追溯来源 | 未表达具体共同细节；组合记录仍与生活原记录混用 |
| 保存与携带 | 本地 IndexedDB；记录、布局、关联统一事务；完整照片 JSON 导出/恢复 | 同浏览器同站点保存；不跨站点/设备同步；容量和回滚存在缺口 |
| 发布与源码 | 已有 GitHub Pages、CI 与受管源码；对应基准 workflow 成功 | 发布可达不代表私人数据同步，也不代表浏览器体验通过 |

默认数据为 17 条：12 条客厅照片故事、2 条池塘照片故事、3 条无照片的原始摆件示例。14 张照片不重复；12 个家具关联对应 8 本书和 4 只抱枕，另有 3 个独立摆件和 2 条鱼。“默认可见 40 件家具”不包含这些额外摆件、鱼或固定建筑。

## 5. 按优先级列出的发现

P0：可能未经用户意愿改变已保存内容，须优先修复。P1：阻碍核心体验、可信保存或自用验证。P2：有明确价值但可在核心片段后改善。优先级不代表已发生事故。

### F01 · P0 · 回滚保护没有覆盖所有用户修改

- **证据**：[rollback-home.mjs](../../dist/rollback-home.mjs)，restoreMomentExamples 第 9–14 行；原测试只覆盖被修改的 note。
- **复现**：从错误版本的隔离 fixture 出发，只改第一条示例的 date 为 2024-04-03，回滚后变成 2026-08-28；只改 rotation 为 1.25，回滚后变成 0。
- **原因**：“未修改”判断只对 title/note/image/palette/form/spot/position 比较，随后整条对象删除重建。date、rotation、scale、localPosition、parentId 等不在比较中。
- **影响范围**：只针对仍待从 personalEdition=1 恢复、且符合示例标记的记录；不能声称普通新记录或所有用户已受影响。已执行过的恢复不能凭代码重建被覆盖值。
- **完成条件**：显式完整版本指纹或用户修改标记；无法判断时保留记录；保留迁移前可恢复副本。补日期/旋转/缩放/局部依附/来源引用/重复迁移用例；恢复原样例和保护用户修改都成立。

### F02 · P1 · 自己导出的备份不一定能恢复

- **证据**：[app.mjs](../../dist/app.mjs) keep、download、settings（47、56、57 行）；[home-data.mjs](../../dist/home-data.mjs) validBackup、portableBackup。
- **复现**：1001 条合法短记录可经 portableBackup 导出，validBackup 返回 false。创建和组合没有同样的记录数限制。
- **另一边界**：单图允许 8 MiB、导入文件最多 100 MiB。10 张接近上限的图，仅 base64 就约 106.67 MiB，尚未算 JSON。是否能在某设备先存够这些图取决于该设备额度；这是算出的不一致，未做浏览器大容量试验。
- **影响**：自用时间越长，越可能到“说导出了，却带不走”的状态。
- **完成条件**：保存、容量提示、导出、导入共享约束；已被应用接受的数据有可恢复路径。分离媒体与预览、采用分文件备份等可选，不能以压缩覆盖原图来隐性解决。验证边界及旧备份兼容。

### F03 · P1 · 输入中断会丢草稿；长文仍不受支持

- **证据**：keep/edit 将文本存在弹窗 DOM，close 直接关闭；重新 open 替换内容。两处 textarea 与导入校验均有 1000 字上限。
- **影响**：地铁中的原始触发恰好容易被打断。写长一些时保存需求被表单边界截住。
- **完成条件**：未保存文字与附件有可恢复草稿；无三维画面仍能记录。用至少 10000 字、中文/换行/emoji 的样例验证保存、编辑、导出和恢复，不能只移除 maxlength。

### F04 · P1 · 示例的“个人视角”不足，物件辨认主要依赖颜色

- **证据**：[demo-memories.mjs](../../dist/demo-memories.mjs) 多数内容为自然景色和观感；[furnishings.mjs](../../dist/furnishings.mjs) 的纹样、书签、配色主要消费 palette/title；keepsake 不读取 note。
- **判断**：当前并非完全没有人称感受，但“什么情况下，我为什么停了一下”较少；八本模板书的差异也容易停在书脊颜色。用户明确指出这一缺口。
- **完成条件**：先只精修 3 个独立演示片刻。每件留下一处源于图文的可辨认细节；真实用户原文不改写。打开后先见原照和那句话，表达说明保持可选。用主人自己的记忆做识别观察，不能让旁人猜故事代替验收。

### F05 · P1 · 来源、纪念物与时间混在一条 record 中

- **证据**：一条 record 同时包含 note/image、form/palette、spot/parentId；edit 更换照片会直接重取色；connect 将合成说明写入一条新 record，date 为今天。
- **影响**：修改原文后无法可靠说明旧作品来自哪个版本；作品生成日期和片刻发生日期混在同一排序中；Cross 容易看起来像多写了一篇程序日记。
- **完成条件**：逐步分出稳定原记录、表示与摆放；保留 source revision，发生/保存/塑形时间各有语义。保持同图单物件约束。数据设计已存在，迁移尚未做，见 memory-and-space.md。

### F06 · P1 · “再次回来”目前主要依赖用户主动想起

- **证据**：物件详情、日期排序和搜索已具备；observation 是固定提示及本次安放 toast 文案，没有持久安放历史、回访记录或连接候选。
- **判断**：安静看水本身可以有价值；尚不能据此证明愿意带回新内容。当前可打开很多物件，但打开前不容易预期会遇到哪段自己的生活。
- **完成条件**：先支持“上次亲手安放的位置”稳定重现，以及用户自选的少量陈列。再试一条可忽略的旧片刻邀请，能回原记录，用户可保留、拒绝或暂停。不要先建通用聚类系统。

### F07 · P1 · 保存失败时，布置画面可能与已存布局不一致

- **证据**：[editor.mjs](../../dist/editor.mjs) up/save 先改变对象，再 await onSave/onMemory；save 不消费失败返回值。[app.mjs](../../dist/app.mjs) changeHome 失败返回 false；家具布局没有恢复到上次已保存快照。
- **影响**：在写入失败路径中，用户可能仍看到新摆放，刷新才发现未留下。这是源码确认的错误处理缺口，未在浏览器注入 IndexedDB 失败。
- **完成条件**：显示待保存/成功/失败的轻量状态，失败可重试或恢复原位置；布置完成不能提前等同于持久成功。测试真实浏览器失败、刷新与拖动中断。

### F08 · P2 · 改过文字的示例仍可能被当作示例收起

- **证据**：edit 仅在换图时设 example=false；只改标题/笔记/日期不更新身份。settings 的“收起示例”按 example 判断。
- **影响**：不会删除原文，但用户已经投入自己的内容后，物件仍会随示例一起消失；在匣中也仍标为示例。
- **完成条件**：将“示例来源”与“用户已认领/修改”分开记录，照片署名可以继续保留；收起示例保护已认领内容。

### F09 · P1 验收缺口 · 移动端、可达性与持续运行没有真实验收

- **证据**：有响应式 CSS、pointer 事件、旋转按钮和高度滑块；首次安放与布置采用两种操作方式。未发现实体物件的完整键盘摆放路径。现有测试运行于 Node。
- **具体风险**：手机无 hover，小书命中与固定 UI 遮挡；首次记录要等大模块加载；频繁 refresh 重建所有独立摆件；纹理异步加载和缓存没有做长期资源压力验证。以上为待测风险，不宣称当前必然卡顿。
- **完成条件**：先验桌面与一部实际手机的核心六步，记录视口、浏览器、触控和失败状态；10 分钟持续交互观察。优先修最小可用目标和无需拖动的替代操作，不启动无证据的大性能重构。

### F10 · P2 · 池塘有回应，视觉融合与记忆差异尚未验收

- **证据**：[courtyard.mjs](../../dist/courtyard.mjs) 的鱼统一缩放 .22，中心位于水面上方 .20；水面最终输出 alpha=1。鱼有复用的流彩材质，路线由稳定 ID 驱动；这不等于真实水下折射或稳定保存的外观版本。
- **风险**：鱼、水面及岸边是否有可信深度和遮挡，必须真实看；现阶段不能称为 Peridot 等级。不同记忆还主要区别在颜色与随机鳍参数。
- **完成条件**：白天/黄昏分别检查身体、眼睛、长鳍和水的层次；只先精修两条默认鱼和一次水面回应，点来的是可认出的既有记忆。再决定是否增加水母或珊瑚。

### F11 · P2 · 用户已接受的箭头仍有一个未闭合的小修改

- **证据**：[navigation.mjs](../../dist/navigation.mjs) 中五块奶油踏石和箭尖石仍在原位置。用户说其他部分很好，希望把长白色物体挪下来；其后要求整轮完整回滚，该改动随之撤销。
- **完成条件**：单独小版本移低/移开白色部分，保留扁箭头位置、轮廓、色调及点击范围。不要借这一项改整个入口。

### F12 · P1 协作缺口 · 多份“当前状态”互相矛盾

- **证据**：README/PROJECT_BRIEF 部分仍写院子未实现、GitHub 尚无授权；CURRENT_SLICE 堆叠多个“当前片段”；DECISIONS 把历史未完成状态与现状放在同表。
- **影响**：下一个代理可能重复开发、沿用已经否定的方向，或把设计文档当成实际功能。
- **本轮处理**：建立独立 CHANGELOG、PROGRESS、ROADMAP 和本报告；CURRENT_SLICE 只保留本轮；旧状态归档；AGENTS 规定每轮必须写结果及验证边界。此项属于本轮修复，其他发现仍开放。

## 6. 与真实需要对照：哪些价值已接近，哪些还没有

| 时刻 | 用户真正想完成的事 | 当前能提供的支持 | 下一轮最小判断 |
|---|---|---|---|
| 车厢里突然想留住 | 不丢掉一个还没想明白的感觉 | 可只写一句并先保存 | 被打断后还能找回；不用马上命名/塑形 |
| 晚上有一点自己的时间 | 把一段生活安放成愿意看的东西 | 真实三维位置、可换模样 | 能挑到“像那一刻”的细节；安放动作不费劲 |
| 隔几天打开 | 重新遇见我自己的生活 | 原图文与空间索引 | 第一眼认出自己曾放在哪里，愿意点开一个 |
| 今天让我想到过去 | 自己发现两次经历的联系 | 手动双来源配色灯 | 新作品包含双方可指认细节，关系由用户承认 |
| 不想整理，只想坐一会儿 | 一个熟悉、没有催促的地方 | 房间、池塘、开关音乐 | 不加记忆也能舒适退出；未安放内容不变成任务债 |

## 7. 可借鉴的参照与边界

[Unpacking 官方介绍](https://www.unpackinggame.com/)明确把安放物品、生活线索和无计时/计分的体验连在一起；其可达性设计也提供无需持续拖动的操作。对本项目的启发是增强放置的可控性与物件线索，让人愿意慢慢看。我们据此提出设计假设，不能据其成功推断私人记忆应用也会留存，更不能复制其虚构人物人生。

[Apple Journal 官方指南](https://support.apple.com/guide/iphone/get-started-iph0e5ca7dd3/ios)已有多种记录材料、写作建议、搜索和日期回看。这提醒我们：保存和找回是需要做稳的基础；本项目值得单独存在的假设在于“我选择的生活在熟悉的位置拥有形态”。不应为了差异化而牺牲基本记录便利。

## 8. 这轮不靠新功能解决的三件事

1. 不必让每段记忆都能被别人猜懂。主人识别和来源可回看比公开可解释性更重要。
2. 不必强求每天打开。以遇到触发时愿意保存、想回望时能回来衡量，安静停留也单独观察。
3. 不必让整个房间全都承担故事。模板家具可以是容器，用户选择留下的小物件才逐步改变它；没有记忆的位置不需要编造历史。

下一步顺序、完成条件、作品集叙事和小规模观察方案见 [ROADMAP](../../ROADMAP.md)。所有发现的执行状态以 [PROGRESS](../../PROGRESS.md) 为准；这份基准审计保留当时事实，不随修复改写历史。
