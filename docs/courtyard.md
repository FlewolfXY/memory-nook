# 院子与池塘：第一次重新遇见

2026-09-08 · 待实施的体验与技术方案。与 docs/memory-and-space.md 配套。

## 1. 第一条完整体验

用户已经保存一段记忆，主动把它的一处细节塑成一条流彩鱼，放进院子的池塘。之后从客厅走到院子，轻触水面，原来的一条鱼慢慢游近；点它，看到对应的片段，并可展开完整原文。关掉详情，鱼继续游，院子继续安静。

此处的惊喜来自“这个地方会回应，而来的东西与我有关”。单独一片好看的水面可以验证氛围，但尚未完成记忆产品的体验。

第一版只需要一个小院、一个池塘、一个可识别的生物表示和一条来源回看链路。数据约定保留水母、珊瑚、植物等表示，不要求它们在这一片段同时完工。

## 2. 童话风、建模友好的空间

沿用客厅的材质和尺度：有厚度的奶油石墙、圆润石块、暖木长凳、鼠尾草绿植物、陶土盆和拱形出口。池水用比室内稍冷的青蓝色，流彩只集中在居民与局部水光，保持记忆物件的辨识度。

取参考的舒缓水面和水边轮廓，不把网页作者的页头、个人导航或整张平面池塘嵌进小屋当作院子。镜头延续小屋的斜俯视，池塘可以靠近观看，但不强制总是完全俯视：先检查鱼在实际展示尺寸下能否看清身体、眼睛和尾鳍。

建模模块：一个地台、少量重复石岸、浅池底、简洁水面、芦苇叶片组、长凳和石台。细节以可复用组件和材质实现，不逐块雕刻大量无交互碎石。

沿用用户“几乎每个小东西都能拿起摆放”的要求：花盆、凳子和纪念物应有独立身份与摆放方式；墙、池体等结构可固定。游动生物由其水域承载，布置时调整栖息区域或迁移到兼容区域，不用把运动中的鱼当普通家具强拖。若要雕塑形态，由用户重新塑形。

## 3. 点击语法

| 动作或状态 | 系统响应 | 数据是否改变 |
|---|---|---|
| 轻触空白水面 | 局部涟漪；选一条可接近的现有鱼作出回应 | 不创建鱼或原记录 |
| 鱼正在靠近 | 沿平滑路线转向，鳍有迟滞，接近后减速停留，再回到游动 | 仅临时运动状态 |
| 再次点击水面 | 更新一次可回应目标；避免无限叠加寻路和涟漪 | 不累积内容 |
| 点击鱼 | 打开来源片段；可展开全文与图片 | 不重新生成 |
| 拖动镜头或布置物件 | 相应操作结束；不误触召鱼或详情 | 仅明确布置动作会保存 |
| 水面被石台或物件遮挡 | 处理可见物件，不隔着遮挡触发水面 | 无 |
| 尚无记忆鱼 | 仍有水光与涟漪；可以邀请用户带一段记忆来 | 不伪造个人记忆 |
| 暂时没有可回应的鱼 | 水面回应即可，不瞬移、不强行打断全部居民 | 无 |

建议首先确定性地选择最近且空闲的一条鱼，便于调试可理解的回应。随机、偏好与群聚以后再引入。点击位置只影响短暂行为，不成为鱼永久归属的位置。

鱼的身份、造型参数、来源与所处水域需要持久化；每帧位置、速度和涟漪无需持久化。刷新后在同一水域重新开始平稳游动，不能每次生成另一条颜色或轮廓完全不同的鱼。

## 4. 附件实际实现了什么

参考：用户上传的 Pasted markdown(20260908-134620).md，1495 行，内含 HTML，标题 Meng Xiang - Interactive Pond。

| 代码位置 | 静态检查到的行为 | 对本项目的意义 |
|---|---|---|
| HTML 的三个 canvas | WebGL 水面、2D Canvas 鱼与涟漪相关动画、2D Canvas 芦苇 | 是分层的平面池塘，不是完整 Three.js 三维院子 |
| FRAGMENT_SHADER | 波纹、渐变水色、边缘软化、噪声纹理 | 可参考柔和池岸与触水反馈的设计 |
| drawFish | 椭圆鱼身、二维尾巴和鳍 | 不具备旧项目 MeshPhysicalMaterial 的流彩材质 |
| setupEventListeners | 点击处 push 一条新鱼；活跃数超过六条后让旧鱼离开 | 我们改用现有居民靠近，不照搬生成/淘汰语义 |
| animate | 简单避边与随机转向，每帧增加位置 | 集成时使用 delta time，避免速度随刷新率改变 |

以上是读代码结果；本轮未运行或录制该 HTML。

## 5. 复用旧水族馆的哪一层

旧项目 /workspace/sites/worldseed-aquarium 保持独立。已核对可作为移植起点的两个模块：

- dist/fish.mjs：圆润身体、眼睛、长尾及背腹鳍；MeshPhysicalMaterial 薄膜虹彩、局部色带流动、边缘高光与按鳍权重延迟摆动。
- dist/lighting.mjs：生成反射环境的 light cards 与 PMREM 贴图。

旧实现仍需视觉验收，不能把“已有代码”写成“已达到 Peridot 品质”。其中用于暗水族馆的光照参数也不能直接当作明亮院子的最终参数。

### 建议集成方式

沿用当前 Three.js，先增加独立 Courtyard 场景或场景根节点，共享一个渲染器、时钟及必要资源。客厅与院子切换时只渲染当前空间，不让隐藏场景继续重绘和响应点击。无需为了这次院子改换整套前端栈。

将鱼的几何/材质与游动控制器分开。行为控制器只负责位置、朝向、速度和回应状态；材质只消费时间与表示参数。使用同一时间基准驱动尾鳍、水面及涟漪，限制页面恢复后的最大时间步。

在 Three.js 水平面上实现水色、缓慢波光和局部涟漪，保留真实深度关系；射线命中实际水域后产生水中目标。鱼在池岸内转向，靠近岸边的点击目标先投影回可游区域。选择命中要考虑前景遮挡，不能沿用“找到任意可移动对象”的穿透逻辑。

最先验证透明水面叠在透明鱼鳍上时的排序与对比度。身体保持实体感，透明主要留给鳍；环境反射和少量流动高光表现虹彩，避免用大面积白色自发光和曝光覆盖细节。接近水面时仍需让眼睛、躯干和尾巴可分辨。

外观表达参数与原图采色分开保存；稳定 seed、模板版本与外观版本使熟悉的居民可以在刷新后认出来。PMREM 和纹理应有共享和释放责任，不在每次点水时重建。

不需要完整流体模拟、复杂骨骼动画、多人服务器或无限生物生成来完成这条体验。

## 6. 验收依据

先用明确标记的样例检验单鱼模型与材质，再接入一条用户保存的记忆；样例不能混入私人原文。

1. 从客厅进入院子再返回，客厅原物件和布局保持；新增模型不打乱旧 ID。
2. 点水十次，原记录数与纪念物数不增加。鱼从原位置转向游近，随后恢复游动；无瞬移和穿岸。
3. 点鱼能打开正确片段，再展开完整长文与原图。关闭详情后不会因同一次点击再次召鱼。
4. 原文修改后旧物件仍能解释其取材版本；主动重做后来源正确。
5. 刷新与导出恢复后，鱼的身份、外观和所处水域保持，移动轨迹无需逐帧复现。
6. 在真实浏览器检查目标尺寸、昼夜、帧率差异、透明排序、遮挡、低运动偏好以及页面切换后的暂停/恢复。记录浏览器和视口，不凭源码判断效果。
7. 用户指出“这让我想起哪一段”，并判断是否愿意在这里停留。技术通过不替代审美与意义的反馈。
